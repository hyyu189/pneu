# Baseline audit — 2026-08-27

> Status: dated snapshot. The audit that anchored the 2026-08-27 rebaseline,
> against public `main` at 23d630e (package 1.3.5). Living truth lives in
> [`../architecture.md`](../architecture.md); this document records the
> verdict, the boundary problems, the do-not-rewrite list, and the
> disposition of every pre-baseline document.

## Verdict

> **The code is well engineered and badly filed.**

The durable messaging and safety core is not throwaway AI code: atomic
publication, ownership checks, UUID-pinned project identity, layout locks,
compare-and-set registry updates, fenced leases, PID/start-fingerprint
liveness, setup backup/rollback, migration recovery, and extensive
crash/retry tests. The risks were elsewhere: product concepts expressed
inconsistently across code and prose; harness facts duplicated across
modules; project initialization taking over too much repository information
architecture; ordinary coordination process committed as long-lived product
knowledge; tests sometimes protecting wording rather than contracts.

## The product-model correction

The old constitution defined a seat as *the human's interactive session*.
The implementation already distinguished stable mailbox identity, one pneu
session ownership term, an optional native thread id, a lease revision, and
advisory surfaces — closer to the corrected ontology than the prose. This
baseline states the contract the code deserves (ADR 0002): **seat = stable
(workspace, harness family) address; a native session occupies the seat;
surfaces display the session.** No runtime field renames were made for the
correction; renames follow only where they improve correctness.

## Strengths that must not be casually rewritten

Durable maildir core; project identity and mailbox migration (frozen
`_rtmigrate.py` and its crash matrices); seat leases and fencing; setup
ownership transaction core; the `_rtsurface.py` boundary; the
process-boundary lock discipline between `rt-ack` and `rt-say`; the live
support discipline separating fixtures from end-to-end evidence.

## Boundary problems carried into the roadmap

One fact, many copies (harness tables, wake predicate, agents.yaml
resolution, safety primitives, launchd logic); duplicated maildir mutation
logic; generic supervised-service machinery named after Codex; hand-wired
doctor/setup dispatch; a packaging manifest that makes decomposition
expensive; a repository-intrusive project scaffold; source-shape and
wording-snapshot tests. Sequenced in [`../roadmap.md`](../roadmap.md)
Phases 2–3.
