# UX and business-logic review — 2026-07-29

> Status: historical record — UX and business-logic review

Method: three parallel read-only review lenses over the user-facing surface —
first-run/onboarding, the daily mail loop, and day-2/recovery/consistency —
plus a doc-cited fact check of Claude Code's multi-agent UI for the
AgentView compatibility question. Static reading only; nothing was executed
that writes state. Line numbers were taken while Codex's M4 work was in
flight and may drift a few lines by the time this is read.

## Verdict

**The safety engineering is ahead of the communication engineering.** The
foundations behave unusually well: preview-then-confirm before every
machine-global write, fail-closed with rollback on every mutation path,
zero observed drift between README/docs and actual code behavior, silent
self-healing when a project moves with its marker intact, and rollback that
quarantines rather than discards conflicting mail. A novice's realistic
failure mode is "it refused with an error," not "it broke my machine."

The debt is one layer up: **the product protects users well but talks to
them badly.** The majority of distinct error strings state a condition
without naming the next command, while the codebase already contains the
good patterns it fails to reuse (`not_project_message()` at
`_rtlib.py:3098`, `rt-doctor`'s unconditional `fix:` lines at
`rt-doctor:745`, the Stop-hook loop-breaker message at
`rt-wait-inbox:305-313` — the best single error string in the product).

## Proposed M5 — the communication batch (all cheap, none breaking)

### M5-1 Wizard resilience (the one real P0)

Every interactive prompt in `bin/roundtable` and `bin/_rtlauncher.py` is
one-shot: any input outside the exact accepted set — including a bare Enter
on a numbered menu (`int("")`) — raises and exits the whole flow
(`roundtable:93-101, 322-325, 404-407, 482-485`;
`_rtlauncher.py:342-361, 397-405, 469-473`). Worse, `choose_seat` runs
*after* `roundtable-init` has already created and registered the project,
and the death message never says the project survived. Fix: bounded
re-prompt (2–3 attempts) on invalid input at every prompt; on any hard exit
after init has applied, print "project already created at X — run
`roundtable` again and choose it from the list."

### M5-2 Observability trio

- **`roundtable version`**: no command reports the live version; `VERSION`
  is printed exactly once ever, at install (`cli.py:787`), and upgrades
  repoint the `current` symlink silently (`cli.py:753-759`). Print version
  + install prefix + current-symlink target.
- **Unknown-target error lists valid names**: `rt-say: unknown agent or
  instance: {target}` (`rt-say:124`) is likely the most common first-command
  typo and no command anywhere lists configured agents/instances. Follow the
  existing good branch (`rt-say:118-121` "use one of: …"): enumerate the
  sender project's `agents.yaml` ids in the error. Same treatment for
  `rt-inbox:507-509`.
- **Dead-seat send advisory**: `rt-say` performs zero liveness check before
  "sent maildir-only" (`rt-say:659-686`). Keep the send unconditional
  (durability is the product), but post-publish, read-only `inspect_seat()`
  and print a non-blocking stderr note when the target is vacant/stale:
  "note: no active seat observed for {target}; mail is durable and will
  deliver when the seat resumes." This is exactly the signal whose absence
  turned the 2026-07-25 unbound-seat defect into days of silence.

### M5-3 Migration's worst-case message

`_commit_observed_after_error` (`_rtmigrate.py:1289-1305`) — the
registry-may-or-may-not-have-flipped path, the worst case in the
crash-safety design — carries zero recovery language, while both its
siblings name their exact recovery ("rerun migrate…", "rerun rollback with
the same manifest…", `:3221-3224`, `:3644-3647`). The recovery sentence
exists only in `docs/install.md:80-81`. Move it into the exception text.
Also: layout/registry lock timeouts (`_rtlib.py:480-515, 1569-1627`) reach
the user as bare "timed out waiting for … lock …" with no hint that another
seat likely holds it, that retry is safe, or that `--layout-lock-timeout`
exists; add one guidance line. And migrate/rollback success is JSON-only
with `sort_keys=True` burying `status` mid-blob (`rt-projects:199`); print
one human line to stderr ("migrated: N files, M bytes; manifest at …")
before the JSON.

### M5-4 Error-string sweep (mechanical, one pass)

- `rt-ack` has no `-h`/`--help` at all — it prints
  `rt-ack: cannot parse msg_id: --help` (`rt-ack:28-37, 111-118`). Found
  independently by two lenses. Add the same hand-rolled help `rt-say` has
  (`rt-say:625-626, 49-66`).
- `rt-ack: cannot parse msg_id: {ref}` — add the expected id shape and a
  pointer to `rt-inbox` (`rt-ack:36`).
- `require_fenced_seat` failures (`_rtlib.py:678-683`) — append the
  doctor-style fix line the codebase already knows how to build
  (`rt-doctor:745-749`).
- `rt-wait-inbox`'s bare not-a-project message (`rt-wait-inbox:99-103`) —
  reuse `not_project_message()` from the same import graph.
- Moved-project (marker-lost) refusal (`_rtlib.py:2193-2204`) — it says
  "tombstone the old registration" without naming
  `rt-projects rm <old-root>` + `rt-projects add <new-root>`; the trivial
  never-registered case does print its literal command (`:2210-2213`).
  Spell out both commands.
- `rt-say` generic `command failed: {oserror}` catch-all also covers the
  primary maildir path (`rt-say:838-843`) — at minimum name the mailbox
  path it was writing.
- Self-send refusal (`rt-say:640, 703`) — decide whether to advertise
  `RT_ALLOW_SELF_SEND=1` (the guard reads it one line above). If the
  omission is deliberate policy, record that; otherwise mention it.
- `validate_agent_component` (`rt-say:158`) — state the allowed pattern.
- `roundtable-setup remove` output — add the "preserved …" enumeration its
  sibling `roundtable-uninstall` already prints (`setup.py:2752-2771` vs
  `cli.py:982-989`).
- Installer PATH line (`cli.py:787-791`) — add the README's own caveat
  ("once per shell; persist it in your shell profile"). Python-not-found
  (`scripts/install.sh:87-94`) — add one line on how to *get* a supported
  Python (brew/python.org).
- `roundtable-init`'s "next:" block (`roundtable-init:505-508`) prints
  mid-wizard right before the wizard does that exact thing; suppress when
  invoked as a subprocess of `bin/roundtable`.
- README: state once that `roundtable setup` ≡ `roundtable-setup` (both
  spellings are used for the same tool in different sections, never
  cross-referenced).

## Explicitly NOT bugs (reviewed, keep as designed)

- `rt-wait-inbox` exiting 2 on the successful `--claude-hook` path is the
  asyncRewake contract (`rt-wait-inbox:503`), intentional.
- `--no-nudge` looks like a no-op but is load-bearing: the Claude
  permission allowlist matches the exact string
  `rt-say --fenced --no-nudge *` (`setup.py:794-798`). It cannot be removed
  without invalidating deployed allowlists. Document, don't delete.
- Durable fire-and-forget send stays; M5-2's advisory is stderr-only and
  post-publish.

## Deferred to v2 (breaking or design-level)

- **Naming system**: the inferable rule "roundtable-* = host lifecycle,
  rt-* = project tools" is violated in both directions — `roundtable-init`
  is per-project scaffolding wearing the host prefix, and `rt-projects` is
  the most host-global tool in the system wearing the project prefix
  (full census in the review transcripts). Renames are breaking; do them,
  if at all, behind aliases in v2.
- **"Give me JSON" has three shapes**: `-f {text,json}` (rt-inbox),
  `--json` (roundtable-setup), format-implicit-per-subcommand
  (rt-projects). Unify on `-f` in v2; `rt-say`/`rt-ack` gain structured
  output for agent callers.
- The setup-apply confirmation screen shows raw plist/permission-rule
  internals (`setup.py:782-798, 2308-2351`); transparent but untranslated.
  Plain-language line per item with raw plan behind a flag. Medium effort.
- `roundtable send` renames the verb (say→send) while `ack`/`inbox` keep
  theirs; `rt-projects list` lacks headers; short-flag coverage is
  incidental. Batch with the v2 naming pass.
- Ordinary unacked mail gets no "this is what keeps re-waking you" framing
  in `rt-inbox` text output (the excellent malformed-mail remedy block at
  `rt-inbox:536-551` shows the shape). Worth doing with the v2 output pass.

## AgentView compatibility (question closed)

Doc-cited facts (Claude Code, mid-2026): agent teams are strictly
session-internal ("one team per session"); SendMessage cannot address
anything outside the session's own spawned team; the agent panel is
CLI-only and shows names+status, not transcripts; there is no API for an
external process to appear in the panel; the only legitimate external
surfaces are SessionStart/SessionEnd async hooks + asyncRewake (already
Roundtable's wake path) and the statusline script, which can *pull*
arbitrary file state on refresh.

Decision: **no integration into Claude's view — steal the job instead.**
The v1 central layout put every mailbox under one root, which is exactly
the observability substrate a cross-harness view needs and which Claude's
panel can never provide (it cannot see Codex, Hermes, or other sessions).
Roadmap: statusline unread-count (cheap, v2); teammate-as-instance —
a Claude teammate holding an `instances:` identity in a sibling worktree —
as a v2 candidate once multi-seat lands; the v3 GUI is a **switchboard**
(projects × seats, unread counts, seat health, jump-to-session) for triage
*between* sessions, not a fleet monitor *within* one.
